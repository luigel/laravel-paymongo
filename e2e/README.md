# End-to-end sandbox

A **real Laravel application** that installs this package from a Composer
`path` repository, runs under Docker, and is exposed to the public internet
through a tunnel so **PayMongo can deliver real webhooks back to it**. The
suite is driven by Pest.

### How this differs from `tests/Contract`

| | `tests/Contract` | `e2e` |
| --- | --- | --- |
| What runs | the package under Testbench | a full Laravel app that `composer require`s the package |
| Direction | outbound only (package → PayMongo API) | outbound **and** inbound (PayMongo → your app) |
| Network | needs internet | needs internet **and** a publicly reachable URL |
| Verifies | request paths, envelopes, statuses | service-provider wiring, published routes, signature middleware, events, artisan commands |
| Runtime | seconds | minutes (scaffolds an app, opens a tunnel) |

Use the contract suite to check PayMongo's API contract; use this to check that
the package actually works when installed in an app.

## Prerequisites

- Docker with Compose v2 (2.24+ — `env_file: required: false` is used).
- A PayMongo **test-mode** secret key (`sk_test_...`). `bin/setup` refuses to
  run with a live key.
- Optional: an ngrok authtoken, and a reserved static domain if you want a
  stable public URL (and thus a reusable webhook registration).

## Usage

```bash
cp e2e/.env.example e2e/.env   # then fill in your test keys
e2e/bin/setup                  # build, scaffold, tunnel, register webhook
e2e/bin/test                   # run the Pest suite (args pass through to Pest)
e2e/bin/teardown               # disable the webhook, stop the containers
```

- `e2e/bin/setup --no-tunnel` skips the tunnel and the webhook registration —
  enough for the tests that do not need inbound deliveries. Every run (with or
  without a tunnel) first blanks `PAYMONGO_WEBHOOK_SECRET` in `e2e/app/.env`,
  because a secret left over from a previous run belongs to a tunnel URL that
  is already dead; the tests that need it skip themselves when it is empty.
- `e2e/bin/test --filter=webhook` — every argument is forwarded to Pest.
- `e2e/bin/teardown --purge` additionally deletes the generated `e2e/app`.

## How it fits together

- `e2e/app/` is generated by `composer create-project laravel/laravel app` and
  is **git-ignored** — it is disposable, never commit it. The package is added
  with a `path` repository pointing at `../..` (the repo root) with
  `"symlink": true`, so your working tree is what the app runs.
- The whole repository is bind-mounted at `/app` in the container and the app's
  working directory is `/app/e2e/app`, which makes `../..` resolve to the repo
  root both on the host and inside the container.
- Files in `e2e/overlay/` (routes, service provider, webhook listener,
  migration, Pest config and the tests themselves) are copied recursively over
  the generated skeleton on **every** `bin/setup` run, so editing the overlay
  and re-running setup is the normal edit loop.
- `bin/setup` registers the webhook by dogfooding the package's own command:
  `php artisan paymongo:webhook:create <tunnel>/paymongo/webhook
  --event=payment.paid --event=payment.failed --event=payment.refunded`. The
  returned signing secret is written to `e2e/app/.env` as
  `PAYMONGO_WEBHOOK_SECRET` and the id to `e2e/.webhook_id` so `bin/teardown`
  can disable it again with `paymongo:webhook:toggle`.
- With **cloudflared** the URL is random and changes on every run, so a fresh
  webhook is registered each time. With **ngrok + `NGROK_DOMAIN`** the URL is
  stable and setup reuses the existing enabled webhook when it can.
- Before probing the tunnel URL, `bin/setup` waits for `dig +short @1.1.1.1
  <host>` to return an address, and only then curls it (falling back to
  `curl --resolve <host>:443:<ip>` when a plain request cannot resolve). A
  brand-new cloudflared hostname is otherwise often asked of the local resolver
  before Cloudflare publishes the record; the cached negative answer then makes
  the reachability check fail with status `000` for minutes even though the
  tunnel is up and PayMongo can reach it. If that still happens, check the
  tunnel log for `Registered tunnel connection` and flush the resolver cache
  (macOS: `sudo dscacheutil -flushcache; sudo killall -HUP mDNSResponder`).

### The tests share SQLite with the HTTP server

The database is a **file**, `e2e/app/database/database.sqlite`, and never
`:memory:`. `bin/test` runs Pest through `docker compose exec` in the *same*
container that runs `php artisan serve`, so a webhook PayMongo delivers to the
running server writes rows the test process can then read — that is the whole
point of the setup. Consequently the E2E tests must not wrap themselves in
`RefreshDatabase`/transactions that would hide the server's writes.

`php artisan serve` re-reads `.env` on each request, so patching
`PAYMONGO_WEBHOOK_SECRET` after the server started needs no restart. Never run
`php artisan config:cache` in this app — it would freeze the config and break
exactly that.

## Safety

- **Test keys only.** `bin/setup` hard-fails on anything that is not
  `sk_test_*`. Test mode moves no real money.
- **Never commit keys.** `e2e/.env` and `e2e/.webhook_id` are git-ignored; only
  `e2e/.env.example` is committed.
- Do not put `PAYMONGO_WEBHOOK_SECRET` in `e2e/.env`: values there are injected
  into the container environment and Laravel's Dotenv does not overwrite
  existing environment variables, so it would shadow the value setup writes
  into `e2e/app/.env`.
- The tunnel makes your machine reachable from the internet for as long as the
  containers run. `bin/teardown` closes it and disables the webhook.
- Each run creates real test-mode resources (payment intents, links, webhooks)
  in your PayMongo test account; they can be cleared from the dashboard.

## CI

`.github/workflows/e2e.yml` runs this suite on **`workflow_dispatch` and a
nightly schedule only** — never on push or pull request. It is slow, it needs
real credentials, and it registers webhooks against a shared PayMongo test
account, so its concurrency group (`paymongo-e2e`) does not cancel in-progress
runs. Required repository secrets: `PAYMONGO_TEST_SECRET_KEY`,
`PAYMONGO_TEST_PUBLIC_KEY`, and optionally `NGROK_AUTHTOKEN` + `NGROK_DOMAIN`
(without them the workflow falls back to cloudflared).
